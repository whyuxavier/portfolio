# whyuxavier — автоматичне портфоліо

Статичний сайт-портфоліо, який сам збирає публічні репозиторії користувача
[whyuxavier](https://github.com/whyuxavier) через GitHub REST API, розкладає їх
за категоріями й показує картки з демо, зірками та посиланням на код.

Без фреймворків, бекенда й збірки — лише HTML, CSS і JavaScript.

## Файли

| Файл | Призначення |
|---|---|
| `index.html` | Розмітка: шапка, hero-ілюстрація, статистика, фільтри, вікно [i] |
| `style.css` | Стилі, темна (за замовчуванням) і світла теми, адаптивність |
| `script.js` | GitHub API, пагінація, кеш, класифікатор, пошук, сортування, картки |
| `categories.json` | Ручні налаштування: категорії, вибрані проєкти, демо, приховування |
| `README.md` | Ця інструкція |

## Як працює

1. Сторінка читає `categories.json`.
2. Якщо в `localStorage` є свіжий кеш (до 30 хв) — показує його без запитів до API.
   Застарілий кеш показується одразу, а дані оновлюються у фоні.
3. Інакше завантажує `GET /users/whyuxavier/repos` посторінково (по 100), доки є `rel="next"`.
4. Форки, архівні репозиторії та сам `portfolio` за замовчуванням не показуються.
5. Для кожного репозиторію визначає адресу демо (див. нижче) і категорію.
6. Фільтри, пошук і сортування працюють локально — без нових запитів.

### Куди веде картка

Пріоритет:

1. `demo` у `categories.json`;
2. поле **Website** (homepage) у налаштуваннях репозиторію — може бути й не GitHub (наприклад, Render);
3. увімкнений **GitHub Pages**: адреса береться з Pages API, а якщо він недоступний без токена — використовується стандартна `https://whyuxavier.github.io/<repo>/` (GitHub сам переадресує її на власний домен, якщо він налаштований). Ця адреса використовується **лише** коли GitHub підтвердив `has_pages: true`;
4. інакше — сам репозиторій.

Кнопка «Код» завжди веде на GitHub, тож навіть якщо зовнішнє демо не працює, код доступний.

### Автоматичні категорії

Зважене оцінювання ключових слів (українською й англійською) у **topics** (вага ×3),
**назві** (×2) і **описі** (×1). Слова порівнюються цілими (а `навч*` — за початком слова),
тому немає хибних збігів на кшталт «гра» всередині «програма».
Навчальна гра потрапляє в «Освіта». Якщо впевненості мало — «Інше».

Порада: додавайте до репозиторіїв topics (`education`, `game`, `tool`, `bot`…) — це найточніший сигнал.

## Налаштування `categories.json`

```json
{
  "settings": {
    "username": "whyuxavier",
    "portfolioRepo": "portfolio",
    "includeForks": false,
    "includeArchived": false,
    "excludeRepos": ["portfolio"],
    "cacheMinutes": 30
  },
  "projects": {
    "назва-репозиторію": {
      "category": "education",
      "featured": true,
      "title": "Гарна назва",
      "description": "Власний опис замість опису з GitHub",
      "demo": "https://example.com/",
      "hidden": false,
      "image": "https://example.com/preview.png"
    }
  },
  "keywords": {
    "education": ["олімпіад*:3"],
    "games": [],
    "tools": [],
    "other": []
  }
}
```

- `category`: `education` | `games` | `tools` | `other` (або `освіта`, `ігри`, `інструменти`, `інше`).
- `featured: true` — проєкт у верхній частині списку з позначкою «Вибране» (у порядку, як у файлі).
- `demo: false` — примусово прибрати демо (картка вестиме на код).
- `hidden: true` — сховати проєкт. `show: true` — показати навіть форк/архів/виключений.
- `keywords` — додаткові слова для класифікатора у форматі `"слово:вага"`, `*` — за початком слова.
- Репозиторії, яких немає (видалені або приватні), просто ігноруються.

**Важливо:** сайт статичний, тож змінити налаштування з браузера неможливо.
Відредагуйте `categories.json` на GitHub (кнопка ✏️ у файлі → *Commit changes*) —
GitHub Pages перебудує сайт за 1–2 хвилини. Щоб побачити зміни одразу, натисніть «Оновити» на сайті
або очистіть кеш сторінки.

## Локальний запуск

`fetch` не працює для `file://`, тому відкривайте через локальний сервер:

```bash
cd portfolio
python -m http.server 8000
# відкрийте http://localhost:8000
```

## Публікація на GitHub Pages

1. **Репозиторій.** У вас уже є `whyuxavier/portfolio` — можна замінити в ньому файли.
   Або створіть новий: <https://github.com/new> → назва, наприклад `portfolio`, тип **Public**.
2. **Файли.** У репозиторії: *Add file → Upload files* → перетягніть `index.html`, `style.css`,
   `script.js`, `categories.json`, `README.md` → *Commit changes*. Файли мають лежати в корені.
3. **Pages.** *Settings → Pages*.
4. **Джерело.** *Build and deployment → Source: Deploy from a branch*, гілка `main`, папка `/ (root)` → *Save*.
5. **Відкрити.** Через 1–2 хвилини сайт буде на `https://whyuxavier.github.io/portfolio/`
   (адреса з’явиться вгорі сторінки Settings → Pages). Додайте її в поле **Website** репозиторію.
6. **Оновлення категорій** — див. розділ про `categories.json`.

Якщо назва репозиторію портфоліо інша, змініть `portfolioRepo` і `excludeRepos` у `categories.json`.

Коли адреса сайту остаточна, можна додати в `<head>` файлу `index.html`:

```html
<link rel="canonical" href="https://whyuxavier.github.io/portfolio/">
<meta property="og:url" content="https://whyuxavier.github.io/portfolio/">
```

## Проблеми

- **«Вичерпано ліміт запитів»** — GitHub дозволяє 60 запитів на годину з однієї IP-адреси без авторизації.
  Сайт робить 1 запит на кожні 100 репозиторіїв і кешує результат на 30 хв, тож для відвідувачів ліміт майже
  недосяжний; частіше він закінчується під час активного тестування. Сайт покаже збережені дані й час,
  коли ліміт оновиться. Токен у фронтенд **не додавайте** — його побачить будь-хто.
- **Нового проєкту немає** — він має бути публічним, не форком і не архівним. Зачекайте 30 хв або натисніть «Оновити».
- **Неправильна категорія** — додайте topics у репозиторій або вкажіть `category` у `categories.json`.
- **Немає «Демо»** — заповніть поле Website у репозиторії (⚙️ біля About) або вкажіть `demo` у конфігурації.
- **Порожня сторінка локально** — відкрийте через `python -m http.server`, а не подвійним кліком.

## Необов’язкове покращення: GitHub Actions

Можна раз на добу генерувати `repos.json` через GitHub Actions (з `GITHUB_TOKEN`, який лишається на сервері)
і читати його замість API — тоді ліміт запитів зникне взагалі. Для поточного обсягу це не потрібно.

## Перевірено

Тести запускались у Chromium (Playwright) з підставленими відповідями GitHub API на основі реальних
даних ваших 17 репозиторіїв (30.10.2026): пагінація (156 репозиторіїв, 2 запити), кеш, ліміт API, збій мережі
й повтор, Pages API з власним доменом, XSS в описі, порожній опис, форки/архіви, пошук українською й англійською,
фільтри разом із пошуком, сортування, вікно [i], тема, клавіатурний фокус, reduced motion, ширини 1280/390/360 px
без горизонтальної прокрутки. Справжній GitHub API з тестового середовища недоступний — після публікації
перевірте сайт наживо.
